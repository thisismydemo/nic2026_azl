# Synthetic RVTools workbook for practice

`IIC-RVTools-demo.xlsx` is a **synthetic RVTools-style Excel inventory** for practising the workload-assessment step of the session (Azure Local Surveyor, Workloads, Import RVTools). It describes a fictional VMware estate for the fictional company IIC (Infinite Improbability Corp).

## Provenance

- **Source:** generated by a script from fixed, fictional inputs. It is not a capture from any real vCenter, it is not an Azure Migrate export, and it contains no measurements.
- **Sanitised by construction:** there is nothing real to remove. Host names use the reserved `.example` domain, IP addresses come from the documentation-only range `192.0.2.0/24`, MAC addresses use the VMware prefix `00:50:56` with sequential values, VM identifiers are synthetic (`42000000-0000-4000-8000-...`), and the file's author property reads "NIC 2026 synthetic demo generator".
- **File integrity:** SHA-256 `480bab6aafd985d5929967d5213e3c00a92006c9802d7c3862c4ff8d038448cf`, 34,256 bytes.
- **Last check:** imported into Azure Local Surveyor v2.8.0 on 2 October 2026; the preview and the dashboard matched the table below.

## What is in it

One vCenter, three ESXi hosts, two VMFS datastores, and Windows and Linux workloads (domain services, web, application, SQL, file, monitoring, management and two legacy VMs). The tabs are `vInfo`, `vCPU`, `vMemory`, `vDisk`, `vPartition`, `vNetwork`, `vCD`, `vSnapshot`, `vTools`, `vSource`, `vCluster`, `vHost`, `vNIC`, `vSwitch`, `vPort`, `vDatastore`, `vHealth` and `DemoNotes` (which repeats the provenance and the expected results). They are representative tabs, not every field or tab of a particular RVTools release.

## How to use it

1. In Azure Local Surveyor open **Workload Planning, Assess existing hardware** and enter your own target nodes (not the source hosts in `vHost`).
2. Go to **Workloads, Import RVTools** and select this file. An import replaces existing inventory rows, so save any existing project first.
3. Check the preview against the table above, then continue to fit, storage design and reports.

## Limits

- It is allocation evidence only: no utilisation percentiles, no application dependencies. Treat missing evidence as an assumption, not as a fact.
- Do not use it as a sizing input for a real project. Use your own RVTools export or an Azure Migrate discovery.
- Surveyor reads `CPUs` as a count, and `Memory`, `Provisioned MiB` and `In Use MiB` as MiB. Keep that unit convention if you edit the file or build your own.
